## 1. 瞄准量：已定案（2026-10-04 20:01 实机日志）

**`human+0x1230` = 俯仰角 A，`human+0x1234` = 偏航角 B（弧度，世界系）。**

玩家朝向（`human+0x60` 矩阵第 3 行）与这两个角的关系，从实测日志逐条对上：

```
fwd = ( sin(B), -sin(A), cos(B) )
```

| 日志一帧 | 检验 |
|---|---|
| `B=1.707, fwd=(0.99,0.03,-0.14)` | `sin(1.707)=0.990`、`cos(1.707)=-0.137` ✓ |
| `B=-0.762, fwd=(-0.69,0.01,0.72)` | `sin(-0.762)=-0.690`、`cos(-0.762)=0.724` ✓ |
| `A=0.019, fwd.y=0.02` | `-sin(0.019)=-0.019`（俯仰上正）✓ |
| `A=-0.259, \|fwd.y\|=0.26` | 量级 1:1，符号取上正下负 |

**基准是世界系**（不是身体系）：玩家原地转身时 `B` 直接跟着世界方位走，而 `pos` 与 `fwd` 都在世界坐标下。
同一段日志里 `off`（准星与最近敌人的夹角）在玩家正对敌人时降到 **2.8° / 3.8°**，
说明 `fwd` 就是"准星指向"，也就是玩家瞄准方向本身。

因此**自瞄的实现就是每帧把这两个角写成"朝目标"**：

```cpp
const float wantYaw   = atan2(tx-px, tz-pz);
const float wantPitch = -atan2(ty-py, horizontalDistance);   // 上正下负
Put<float>(human, 0x1234, wrap(wantYaw));
Put<float>(human, 0x1230, clamp(wantPitch, -pi/2, pi/2));
```

`src/playeraim.cpp` 的 `Watch` 就是这么做的（`PlayerAimSteer=1` 打开，`PlayerAimGain` 控制每帧走多少）。

### 实测验证（2026-10-04 20:12，同一台机器、同一张图）

同一位玩家、同一关，先跑"只观测"的一版（20:01），再跑"自瞄开启"的一版（20:10–20:12），
日志里 `PLAYERAIM` 的 `off`（准星与最近敌人的夹角，度）对比：

| 版本 | `off` 观察值 |
|---|---|
| 只观测（无写入） | 3.8 / 41 / 85 / 92 / 104 / 108 / 26 / 53 / 40 …（跟着手动视角走） |
| **自瞄开启** | **0.2 / 0.1 / 2.5 / 0.3 / 0.5 / 0.1 / 0.4 / 0.2 / 0.0 / 0.7 / 0.9 / 0.3 / 0.1 / 0.3 / 0.5** |

即准星被稳定压在 **1° 以内**，而且 `off` 只在玩家刚被传送到新位置、目标切换的瞬间短暂变大
（日志里 20:12:19.652 那一帧 `off=33.9` 正是目标切换，下一帧即回到 0.1）。
同时玩家自己在走动（`pos` 一直在变），说明是"边走边锁"，不是静止摆拍。

日志里的配置行与钩子行完整对得上：

```
CONFIG playerAim=1 fire=1 steer=1 gain=0.35 range=200
HOOK player aim=4/4 (input slot 4 of the human vtables)
HOOK player aim barrels=5/5 (call sites of the muzzle builder)
```

### 备用路径：直接改弹道（`PlayerAimFire`）

瞄准角之外还有一条更硬的保险：**枪口构造 `0x6969a0`** 决定弹丸出膛方向，它把「枪口局部矩阵（`+0x10`）」
与一个瞄准基（调用方传 `weapon+0x150`）相乘；模式 0 直接用传入的基，模式 1/2 用 `rdx+0xB0`。
插件的 `MuzzleHook` 在这 5 个调用点之前把瞄准基的第 3 行换成"朝目标"的基，弹道即被拧过去。
调用点全部装上了（日志 `barrels=5/5`）。

**但步行时它不会触发**：日志里 `gun=0000000000000000 / mmode=-1`，因为玩家不在座位上时，
`FirstWeapon` 走的"座位武器链"拿不到武器；步行用的武器集合（`human+0x1950` 那张表，
准星绘制 `0x803be8` 读的 `[[[human+0x1950]+id*8]]+0xD8`）还没接上。
自瞄本身不依赖这条路径（20:12 的实测就是纯靠瞄准角），所以它现在只是"开火瞬间的额外保险"，
对步行玩家暂不生效——接上武器集合后即可覆盖。

### 实机验证方案（下一步）

诊断优先，一步就能定案：

1. `HumanBase` slot 4（`0x572df0`）装一个"前/后"钩子，只对 `crew::PlayerHuman()` 认出的本地玩家动作：
   - 钩子前记下 `human+0x60..0x90`（朝向与位置）、`+0x1230`/`+0x1234`、`+0x1d0`；
   - 钩子后再记一次，`Debug=1` 时打日志（`AIM v=%p yaw=%.3f pitch=%.3f fwd=(%.2f,%.2f,%.2f)`）。
2. 对照实验：`AimTest=0.3`（ini）时，钩子后**只**给其中一个字段加一个固定量，看准星/弹着点动没动、
   往哪边动。一次改一个字段，日志里记下"改前/改后 + 玩家朝向 + 目标方向"，一次实机就能把
   **哪个字段是瞄准方向、符号是什么、角度基准是身体还是世界** 三件事一起定下来。
3. 定案后按 `autoturret/src/plugin.cpp` 的稳态做法实现：目标选取（复用锁定注册表 + 队伍关系）、
   迟滞（当前目标保留到死亡 / 出界）、手动脉冲（摇杆/鼠标动过就先让人）、
   `Gain` 比例的闭环（和炮塔的 `AxisInput` 同款），写入确认过的那个量。

## 3. 与 `autoturret` 的关系

炮塔自瞄改的是**载具座位上的转向输入**（`veh+0x2aa0 + seat*0x10`），步兵没有座位，改的量不同，
但**目标选取、队伍过滤、迟滞、闭环增益、日志** 全部可以照搬 `autoturret/src/turret.h` 那一套，
敌人快照也直接用 `heli.cpp` / `turret.h` 读的同一个锁定注册表。

## 4. 实机核对清单（2026-10-04 已逐条有结论）

| 问题 | 结论 |
|---|---|
| `human+0x1230`/`+0x1234` 是瞄准角还是视线测距结果？ | **是瞄准角**（俯仰 / 偏航）。写进去后 `off` 从几十度收敛到 1° 以内（20:12 实测）。 |
| 基准是身体还是世界？ | **世界系**（§1 的表格）。所以不需要减去身体偏航。 |
| 偏航/俯仰的符号与 0 方向？ | `fwd=(sin B, -sin A, cos B)`；偏航 0 指向 +Z、向 +X 增大；俯仰正 = 向上。 |
| 步行 / 乘车路径是否同一套？ | 瞄准角两条输入路径都写（`0x572df0` 与 `0x470ca0`），步行实测生效。乘车时准星归载具，本功能应让位（`PlayerHuman` 仍能认出玩家，但载具的瞄准走座位链，本模块不碰）。 |
| 弹道取枪口矩阵还是武器自身朝向？ | 取「枪口局部矩阵 × 瞄准基」，瞄准基里模式 0 用 `weapon+0x150`、模式 1/2 用 `rdx+0xB0`——所以 `MuzzleHook` 换掉瞄准基即可改弹道（5 个调用点全部挂上）。 |
| 联机 | 与 `autoturret` 同一注意事项：只写本机玩家的那两个字段，别人由他们自己的机器模拟。未联机测试。 |

## 5. 已知的下一步（可选）

1. **步行武器集合**：把 `human+0x1950` 那张表接上（`[[[human+0x1950]+id*8]]+0xD8` 返回武器，
   准星绘制 `0x803be8` 就是这么取的），`PlayerAimFire` 才能在步行时生效——自瞄本身不依赖它。
2. **手动脉冲**：现在每帧都覆盖瞄准角，玩家自己推右摇杆/鼠标时会被自瞄拉回来。
   照 `autoturret` 的 `DragDeadzone` 做法，检测到玩家输入就短暂让位。
3. **目标迟滞**：现在每帧取最近敌人，目标在等距附近可能来回切（20:12 日志里那一次
   `off=33.9` 的跳变就是换目标）。照 `autoturret` 的 `SlewWeight` / `kKeepTarget` 加迟滞。
4. **提前量/弹道下坠**：目前直接指当前敌人位置。远距离抛物线武器（火箭筒等）可照
   `autoturret` 的 `Ballistic` 解算提前量。
